# Genre: System / Design Science / HCI paper

Do not conflate design concepts, working features and validated benefits. Route argument: evidence-based requirements → design rationale and alternatives → architecture with provenance → implemented features and integration → functional tests → expert/user evaluation → error cases → operational impacts *only if measured*. Map requirements one-to-one to evidence and verification, then discuss trade-offs and future work.

Research contributions are not a list of UI features. Explain what design knowledge, empirical results, method or validated principle can be transferred. A clickable prototype can demonstrate flow feasibility, not prove improved learning, safety or efficiency. Use relevant human-in-the-loop/decision validation metrics when applicable.
